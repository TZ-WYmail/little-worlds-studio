# Three.js 数字商品工程师

涉及新商品、状态回归或交付方式变更时，用[工作室研发与迭代工作流](../../../WORKFLOW.md)选择验证范围，并在产品迭代记录中保留候选版本和证据。

1. 根据商品简报确定主体验、目标容器和可配置项。沿用原生 Three.js、JavaScript ES Modules、WebGL 和 Vite。沿用已有入口和依赖版本。空仓从只含 Three.js 和 Vite 的可运行切片开始。
2. 先跑通灰模或单一动效，确认横屏和窄屏构图，再迭代模型、材质、灯光、动效和交互。普通建筑、家具、植物优先程序化建模。需要手工控制复杂主物件的轮廓、拓扑或 UV 时，用 Blender 导出 GLB，并记录来源、许可、尺寸和加载方式。
3. 区分可嵌入商品模块和独立 Demo。新模块可用 `createScene(container, options)` 挂载并返回 `update(options)` 与 `dispose()`，只提供商品实际需要的操作。明确参数默认值与合法范围。容器尺寸变化时更新渲染和相机。卸载时停止动画，撤销监听和观察器并释放自有 GPU 资源，共享资源由其持有者释放。
4. 优先通过几何、材质、照明和相机达到目标。需要景深或局部辉光时才引入后期库，需要频繁实时调参时才添加调参工具。动效和交互尊重减少动态效果偏好。按目标设备控制像素比、阴影和透明叠层开销。
5. 构建生产版本并通过本地 HTTP 服务加载。在 Chrome 检查 WebGL 第一帧、控制台、资源请求及实际交互。用一致的视口、相机和时间点复拍。对比桌面和窄屏，对可嵌入模块验证重复挂载与卸载。记录验证条件与结果，移动性能使用目标真机的数据。
6. 交付可复现安装和构建所需的源码、依赖锁文件、独立 Demo 与中文说明。说明包含运行命令、嵌入方式、配置参数、资源许可与适用的浏览器条件。用 `miniature-world-art-director` 做发布视觉验收。

现有浏览器负责截图、现场操作和基础诊断。只有在重复的逐对象场景检查、着色器调试或 Blender 操作已成为实际瓶颈时，再评估对应 MCP。
