# 蓝花楹书店迭代与复盘

**基线 · 2026-11-21 整理 · 手机单文件候选**

项目从《Jacaranda Bookshop》静态展示策划起步，随后按实际试用反馈改成可漫游的明信片。记录依据是初版策划、用户的历轮反馈、2026-11-20 本地历史归档、当前源码和 [运行验收](QA.md)。两张成熟作品截图提供了光影、天气与界面层次的观察基准。使用[总仓库工作流](../../../WORKFLOW.md)继续登记。

## 这次返工给流程带来的改变

1. **首个切片必须能证明主要体验。** 静态构图可以判断比例。需求转成可漫游后，最早的交付应该包含真实输入、镜头响应和回到全景。加载出的静态封面也有单独的降级验收。
2. **先看光落在哪里，再精修模型细节。** 第一轮反馈解释了为什么做完模型仍缺氛围。对照同时要看窗内、窗下、树下和湿地，检查主光来源、遮挡和远近层次，再决定是否需要增加几何细节。
3. **把系统状态作为一组来验收。** 白昼亮灯涉及灯源、材质、光晕与受光粒子。时间和天气修改需要覆盖交叉组合及回切。结构拆解和薄雾退出当前范围后，同步以当前范围复查入口和说明。
4. **把设计形容词转成具体画面。** 「高级」对应统一的明信片版式、真实背景上的题字对比度和控件层次；「空」对应右栏落款及通往后巷的有效入口。窄屏的布局要一起验收。
5. **产品的传递路径属于体验。** 先明确接收者打开的是静态预览、网页还是 HTML 文件。资源与署名随同交付，验证从空目录运行。区分模拟验证和真机验证，再决定可声称的兼容范围。

## 当前约定与回归矩阵

时间为 **Daylight / Dusk / Night**，天气为 **Clear skies / Spring rain**。正面窗光从内部透出，后门局部壁灯随时刻联动。结构拆解和薄雾已退出当前操作界面。

| 触发改动 | 先跑的检查 | 通过条件 |
| --- | --- | --- |
| 灯光、玻璃或天气 | 固定橱窗镜头，白昼晴空 → 深夜晴空 → 深夜春雨 → 白昼春雨 → 返回白昼晴空，再补傍晚两种天气。 | 白昼无人工发光，窗光与真实开口一致，夜雨有位置正确的暖光和湿地反射。同机同条件下白昼恢复到初始观感。 |
| 背面或壁灯 | **Back lane** 在白昼、傍晚和深夜各观察一次，再回 **Overview**。 | 门灯位置可辨，白昼熄灭，局部暖光照到台阶，从默认视角按预期被建筑遮挡。 |
| 交互或明信片 | 桌面和 390、320 CSS 像素检查六种时刻天气组合、拖动、双指缩放和预设回全景。额外抽查断点附近与键盘焦点。 | 无横向溢出，题字能读，控件能点，拖动与缩放改变实际取景，查看后巷和低动态模式仍可操作。 |
| 音源或交付包 | 分别执行 `npm run build` 与 `npm run build:mobile`。把产物复制到空目录，从本地文件断网打开。 | 首载静音，音乐启停和轮播正常。内嵌许可可查。禁用脚本或 WebGL 时有静态封面。 |
